164: Rows read measure how many rows a query reads (scans), regardless of the size of each row. For example, if you have a table with 5000 rows and run a SELECT * FROM table as a full table scan, this would count as 5,000 rows read. A query that filters on an unindexed column may return fewer rows to your Worker, but is still required to read (scan) more rows to determine which subset to return. 
165: Rows written measure how many rows were written to D1 database. Write operations include INSERT , UPDATE , and DELETE . Each of these operations contribute towards rows written. A query that INSERT 10 rows into a users table would count as 10 rows written. 
166: DDL operations (for example, CREATE , ALTER , and DROP ) are used to define or modify the structure of a database. They may contribute to a mix of read rows and write rows. Ensure you are accurately tracking your usage through the available tools ( meta object , GraphQL Analytics API , or the Cloudflare dashboard ↗ ). 
168: Defining indexes on your table(s) reduces the number of rows read by a query when filtering on that indexed field. For example, if the users table has an index on a timestamp column created_at , the query SELECT * FROM users WHERE created_at > ?1 would only need to read a subset of the table. 
169: Indexes will add an additional written row when writes include the indexed column, as there are two rows written: one to the table itself, and one to the index. The performance benefit of an index and reduction in rows read will, in nearly all cases, offset this additional write. 
170: Storage is based on gigabytes stored per month, and is based on the sum of all databases in your account. Tables and indexes both count towards storage consumed. 
171: Free limits reset daily at 00:00 UTC. Monthly included limits reset based on your monthly subscription renewal date, which is determined by the day you first subscribed. 
173: Read replication does not charge extra for read replicas. You incur the same usage billing based on rows_read and rows_written by your queries. 
177: Will D1 always have a Free plan? 
178: Yes, the Workers Free plan will always include the ability to prototype and experiment with D1 for free. 
179: What happens if I exceed the daily limits on reads and writes, or the total storage limit, on the Free plan? 
180: When your account hits the daily read and/or write limits, you will not be able to run queries against D1. D1 API will return errors to your client indicating that your daily limits have been exceeded. Once you have reached your included storage limit, you will need to delete unused databases or clean up stale data before you can insert new data, create or alter tables or create indexes and triggers. 
182: What happens if I exceed the monthly included reads, writes and/or storage on the paid tier? 
183: You will be billed for the additional reads, writes and storage according to D1's pricing metrics .
