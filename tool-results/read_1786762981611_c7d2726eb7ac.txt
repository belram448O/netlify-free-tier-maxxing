     1→# Netlify Free Tier — Deep Research & Hands-On Validation Findings
     2→
     3→**Research date:** 2026-08-14
     4→**Method:** Official docs review + community research + hands-on API probing + real E2E scrape deployment
     5→**Account tested:** `belram448O's team` (Free, credit-based, post-Sep-2025 model)
     6→**Credits at start:** 300
     7→**Credits at end:** ~180 (8 prod deploys × 15 credits = 120 consumed; preview deploys + blob ops = 0)
     8→
     9→---
    10→
    11→## Executive Summary
    12→
    13→Netlify's Sep 4, 2025 pricing revamp replaced the generous legacy free tier (100GB bandwidth, 125k function calls, 1M edge invocations, 300 build minutes — all separate) with a single shared pool of **300 credits/month** that must cover production deploys, compute, bandwidth, web requests, and AI inference all at once. One site exceeding the pool pauses every site on the account.
    14→
    15→Despite this constraint, hands-on testing confirmed multiple genuinely free paths that can be leveraged for scraping / data pipelines / background compute workloads — the most important being:
    16→
    17→1. **Preview deploys (`draft: true` / `netlify deploy` without `--prod`) = 0 credits, fully metered as free**
    18→2. **Netlify Blobs storage = unmetered for both at-rest storage AND API read/write traffic** (verified: 10+ MB transfer through blob API = 0 credits)
    19→3. **Build process = up to 15 min of free compute per preview deploy** with 2 vCPU, 4 GB RAM, 9 GB disk, outbound HTTP, npm install, can run headless Chrome via `@sparticuz/chromium`
    20→4. **Build plugins (`onPostBuild`) can write to Blobs** via auto-injected `NETLIFY_BLOBS_CONTEXT` env var — same env var is NOT available in the build command phase, only in plugins
    21→5. **Per-org quota rotation (Supabase-style) does NOT work** — one Free team per Netlify user, hard API-enforced

    25→## Part 1: Netlify Pricing Revamp (Sep 4, 2025)
    26→
    27→### What changed
    28→
    29→| Dimension | Legacy "Starter" (pre-Sep-2025) | New "Free" (credit-based) | Net change |
    30→|---|---|---|---|
    31→| Bandwidth | 100 GB/month hard cap | ~15 GB max if all 300 credits spent on bandwidth | ~6.7× smaller, shared with everything |
    32→| Serverless functions | 125k invocations/site/month | ~30 GB-hours of compute (if 100% of credits spent on compute) | Massively smaller, per-team not per-site |
    33→| Edge function invocations | 1M/month | ~1.5M max (if 100% of credits on web requests) | Smaller in practice |
    34→| Build minutes | 300 min/month hard | Not metered (but each prod deploy = 15 credits) | Different shape |
    35→| Forms submissions | 100/site/month | Free and unlimited | Improvement |
    36→| Sites/projects | 500 | 500 (sharing one 300-credit pool) | Same cap, smaller effective budget |
    37→| When limits exceeded | Hard stop on that meter | All projects paused until next cycle | Worse blast radius |
    38→
    39→### Credit meter rates (post-Apr 2026)
    40→
    41→| Meter | Credit rate | Notes |
    42→|---|---|---|
    43→| Production deploys | **15 credits each** | Failed deploys & rollbacks free; previews/branch deploys 0 credits |
    44→| Compute | **10 credits / GB-hour** | Functions + scheduled + background + Agent Runners + DB compute. **Wall-clock** time × memory |
    45→| AI inference | 180 credits / $1 USD | Agent Runners + AI Gateway |
    46→| Bandwidth | **20 credits / GB** | Web egress + DB egress |
    47→| Web requests | **2 credits / 10,000 requests** | Page views, function API calls, asset requests, Edge Function invocations |
    48→| Forms submissions | **Free / unlimited** | All credit plans |
    49→
    50→### Legacy grandfathering
    51→
    52→- Accounts created before Sep 4, 2025 are automatically grandfathered with old quotas
    53→- Switching to credit-based is **irreversible** — cannot revert
    54→- Netlify Database, Agent Runners, AI Gateway are credit-plan-only (legacy accounts cannot use them)
    55→
    56→### Per-user enforcement (Supabase-style rotation NOT possible)
    57→
    58→Hands-on API test confirmed:
    59→- `GET /accounts/types` returns Free plan with `available: false` once user already owns one Free team
    60→- `POST /accounts` with Free `type_id` returns `422 "Account plan is unavailable to this user"`
    61→- Netlify staff confirmed on forum: "You can only create a single Free team"
    62→- The binding identity is the Netlify user (email + OAuth), not the team
    63→
    64→**Practical maxxing = N distinct Netlify users (separate email + GitHub identity each) = N × 300 credits, fully siloed. Heavy operational tax.**

    68→## Part 2: Netlify Blobs — Ground Truth (Hands-On Validated)
    69→
    70→### What the docs say
    71→
    72→Blobs documentation lives at `docs.netlify.com/build/data-and-storage/netlify-blobs/`. Lists only technical limits:
    73→
    74→| Limit | Value |
    75→|---|---|
    76→| Max object size | 5 GB |
    77→| Max object metadata | 2 KB |
    78→| Max object key length | 600 bytes |
    79→| Max store name length | 64 bytes (no `/` or `:`) |
    80→| Per-store total size cap | **None documented** |
    81→| Per-account total size cap | **None documented** |
    82→| Operations (reads/writes) cap | **None documented / not metered** |
    83→
    84→**Critical:** The Blobs page does NOT mention billing, credits, quota, or a "free until" date. Compare to Netlify Database which has an explicit `/billing-and-usage/` page stating storage is "free until July 1, 2026."
    85→
    86→### What the API says (verified)
    87→
    88→The 6 credit meters are:
    89→1. Production deploys
    90→2. Compute
    91→3. AI inference
    92→4. Forms (free)
    93→5. Bandwidth
    94→6. Web requests
    95→
    96→**There is NO `blobs_storage`, `blob_count`, or `blob_operations` meter anywhere** — not in the docs, not in the usage dashboard, not in the credit table, not in the `GET /accounts` capabilities object, not in the SDK.
    97→
    98→### Hands-on credit-metering tests
    99→
   100→| Test | Bytes transferred | Credits consumed |
   101→|---|---|---|
   102→| Read 446 KB blob × 20 times via REST API | ~9 MB | **0** |
   103→| Write 1.4 MB blob via direct API PUT (presigned URL) | 1.4 MB | **0** |
   104→| Read 1.4 MB blob back via API | 1.4 MB | **0** |
   105→| Write 709 KB blob from build plugin via @netlify/blobs SDK | 709 KB | **0** |
   106→| **Total transferred through Blobs API** | **~12 MB** | **0 credits** |
   107→
   108→**Conclusion: Netlify Blobs is genuinely unmetered storage.** At-rest storage is free, and API read/write traffic does not touch the bandwidth meter.
   109→
   110→### Blobs infrastructure
   111→
   112→Hands-on API probing revealed:
   113→- **Backend = AWS S3** in `us-east-2` (Ohio)
   114→- Bucket hostname: `cmh-services-prod-netliblob-935421240257.s3.us-east-2.amazonaws.com`
   115→- Write pattern = presigned S3 URLs:
   116→  1. `PUT /api/v1/blobs/{site_id}/{store}/{key}` with header `Accept: application/json;type=signed-url` → returns `{url: <presigned S3 URL>}`
   117→  2. Client uploads bytes directly to S3 via the presigned URL
   118→- Read pattern = direct API GET returns blob content
   119→- NOT Deno KV, NOT Cloudflare R2 — it's S3 under a KV abstraction
   120→- The Blobs SDK only knows 5 AWS regions: `us-east-1`, `us-east-2`, `eu-central-1`, `ap-southeast-1`, `ap-southeast-2`
   121→
   122→### REST API surface (not in public OpenAPI spec)
   123→
   124→The public OpenAPI spec at `open-api.netlify.com/openapi.json` (v2.57.0, 111 paths) contains **ZERO blob endpoints** — they're undocumented. The actual endpoints (discovered via SDK source + probing):
   125→
   126→| Method | Path | Auth | Purpose |
   127→|---|---|---|---|
   128→| `GET` | `/api/v1/blobs/{site_id}` | User PAT works | List stores: `{"stores":["site:foo","site:bar"]}` |
   129→| `GET` | `/api/v1/blobs/{site_id}/{store}` | User PAT works | List blobs in store: `{"blobs":[{key,size,etag,last_modified}],"directories":[]}` |
   130→| `GET` | `/api/v1/blobs/{site_id}/{store}/{key}` | User PAT works | Read blob content (returns raw bytes) |
   131→| `PUT` | `/api/v1/blobs/{site_id}/{store}/{key}` | User PAT works | Get presigned S3 URL, then upload to S3 |
   132→| `HEAD` | `/api/v1/blobs/{site_id}/{store}/{key}` | Blobs token only | Check existence (401 with user PAT) |
   133→| `DELETE` | `/api/v1/blobs/{site_id}/{store}/{key}` | Blobs token only | Delete blob (401 with user PAT) |
   134→
   135→Store naming: `site:{name}` (the `site:` prefix is mandatory in REST paths).
   136→
   137→### Blobs token vs User PAT
   138→
   139→- **User PAT** (e.g., `nfp_...`): can do read-only listing + GET reads + PUT (via presigned URL) on the REST API
   140→- **Blobs token**: required for HEAD, DELETE, and for the Edge plane API. Auto-injected into Netlify Functions/Edge Functions/Build plugins via `NETLIFY_BLOBS_CONTEXT` env var (base64-encoded JSON with `{apiURL, edgeURL, uncachedEdgeURL, siteID, token, primaryRegion, deployID}`)
   141→- The Blobs token is NOT retrievable via REST API with a user PAT — only available inside Netlify runtime contexts

   168→### Credit metering reality (API lags dashboard)
   169→
   170→| Source | Sees credits in |
   171→|---|---|
   172→| `GET /api/v1/accounts` `capabilities.credits.used` | **5–30+ minutes lag** |
   173→| Dashboard at `app.netlify.com` | Real-time |
   174→
   175→During testing, the API showed `0/300` while the dashboard showed `180/300` (120 credits consumed across 8 prod deploys). **Always trust the dashboard for real-time credit state.**
   176→
   177→### Build → Blobs pipeline (validated)
   178→
   179→The `NETLIFY_BLOBS_CONTEXT` env var is:
   180→- ❌ NOT available in the build command phase (`node src/scrape.js`)
   181→- ✅ Available in build plugin `onPostBuild` hook
   182→- ✅ Available in Netlify Functions
   183→- ✅ Available in Edge Functions
   184→
   185→So the pattern is:
   186→1. Build command writes data to `/tmp/` (shared filesystem within the build container)
   187→2. Build plugin's `onPostBuild` hook reads `/tmp/` files and writes to Blobs via `@netlify/blobs` SDK
   188→
   189→### Deploy contexts and credit costs
   190→
   191→| Context | How to trigger | Credit cost |
   192→|---|---|---|
   193→| `production` | `netlify deploy --prod` OR `POST /sites/{id}/deploys` (default) | **15 credits each** |
   194→| `deploy-preview` | `netlify deploy` (no `--prod`) OR `POST /sites/{id}/deploys` with `draft: true` | **0 credits** |
   195→| `branch-deploy` | Push to non-prod Git branch | **0 credits** |
   196→
   197→**Key finding:** `POST /api/v1/sites/{site_id}/deploys` with body `{"draft": true, "files": {...}}` creates a `context: deploy-preview` deploy via API — same as `netlify deploy` CLI without `--prod`.
   198→
   199→### Build hooks (NOT a free trigger without Git)
   200→
   201→- `POST /api/v1/sites/{site_id}/build_hooks` creates a hook URL like `https://api.netlify.com/build_hooks/{id}`
   202→- POSTing to that URL returns `HTTP 200` but **does NOT trigger a build if the site has no Git repo connected**
   203→- Build hooks require a Git-connected site to actually fire a build
   204→- Workaround: use `POST /sites/{id}/deploys` with `draft: true` + PAT in Authorization header (requires PAT, not anonymous)
   205→
   206→### Scheduled functions (did NOT reliably execute in this account)
   207→
   208→- `POST /api/v1/sites/{id}/functions/{name}/invoke` returns `HTTP 202 "triggered successfully"` but function never actually ran in our tests
   209→- Cron `*/5 * * * *` schedule registered correctly in function metadata (`schedule: "*/5 * * * *"`) but no blob ever got written by the function
   210→- Function-logs API is gated behind Pro plan — couldn't see why it failed
   211→- **May be sandbox-specific or may be a real Free-plan limitation. Unverified.**
   212→
   213→### Real E2E scrape (validated working)
   214→
   215→**Run 1 (smaller):**
   216→- 200 stories + 608 comments = 808 items scraped
   217→- 446 KB raw JSONL stored in Blobs
   218→- 7.5 KB processed JSON stored
   219→- Build time: 186 seconds
   220→- Credits consumed: 0 (preview deploy)
   221→
   222→**Run 2 (bigger):**
   223→- 500 stories + 820 comments = 1,320 items scraped
   224→- 693 KB raw JSONL stored in Blobs
   225→- 7.5 KB processed JSON stored
   226→- Build time: 289 seconds (~4.8 min)
   227→- Credits consumed: 0 (preview deploy)
   228→
   229→**Run 3 (oversize, failed):**
   230→- 500 stories + 3,000 comments + dump entire raw to stdout in one `process.stdout.write()` call
   231→- Build got stuck (state stayed `new` for 20+ min past 15-min cap)
   232→- Cancelled via `POST /deploys/{id}/cancel`
   233→- **Root cause:** Single-shot `process.stdout.write()` of multi-MB strings appears to choke Netlify's log ingester
   234→- **Fix:** Stream log output line-by-line via `readline.createInterface` — worked in Run 2

   285→## Part 5: Account-level SSO gotcha
   286→
   287→This account has `account_sso_login: True, account_sso_login_context: "all"` hard-enforced. Even production URLs require Netlify login to access. Cannot be disabled via API:
   288→- `PATCH /accounts/{id}` with `site_sso_login_context: "none"` returns `null` for that field, but the value stays `all`
   289→- `PATCH /sites/{id}` with `sso_login: false` returns `null`, but `account_sso_login` stays `True`
   290→
   291→This is likely a security default for GitHub-OAuth-only accounts (no verified email). Real Netlify accounts with verified emails typically have public production URLs.
   292→
   293→**Impact:** Cannot curl a function URL or static asset URL anonymously — all return `HTTP 401` with a redirect to `app.netlify.com/edge-access`. However, **Blobs API still works with PAT** — the SSO gate is on the public CDN, not the data API.

   308→| Edge reach | Single region (functions) | Global ~330+ cities | **CF** |

   312→| Build minutes | Not metered (prod deploys cost 15cr) | 500 builds/month | Different shape |
   313→| Forms | Free & unlimited | N/A | **Netlify** |
   314→| Preview DB branches | Yes (Neon) | Manual | **Netlify** |

   569→- **JA4-aware bot detection:** Same — extension hash unchanged in our test.

   599→### Working TLS impersonation setup
   600→
   601→**`functions/package.json`:**
   602→```json
   603→{
   604→  "name": "functions",
   605→  "version": "1.0.0",
   606→  "private": true,

   609→    "@netlify/blobs": "^8.0.0",

   616→```toml
   617→[build]
   618→  command = "npm install"
   619→  publish = "src"
   620→  functions = "functions"

   622→[functions]

   624→  external_node_modules = ["tls-impersonate"]
   625→  included_files = ["functions/node_modules/**"]

   628→**Critical:** Function file MUST be `.mjs` (ESM), because `tls-impersonate` is ESM-only. CommonJS `require()` fails with `ERR_REQUIRE_ESM`.
   629→
   630→### The function pattern
   631→
   632→```js
   633→// functions/scrape.mjs
   634→import tls from 'node:tls';
   635→import { impersonate, isSupported } from 'tls-impersonate';
   636→
   637→export async function handler(event, context) {
   638→  if (!isSupported()) {
   639→    return { statusCode: 500, body: 'tls-impersonate not supported on this runtime' };
   640→  }
   641→
   642→  // Chrome 120 ClientHello spec
   643→  const CHROME_SPEC = {
   644→    cipherSuites: [
   645→      0x1301, 0x1302, 0x1303, // TLS 1.3
   646→      0xc02b, 0xc02f, 0xc02c, 0xc030, // ECDHE
   647→      0xcca9, 0xcca8, // CHACHA20
   648→      0xc013, 0xc014, // Legacy ECDHE-SHA
   649→      0x009c, 0x009d, 0x002f, 0x0035, // Legacy RSA
   650→    ],
   651→    extensions: [
   652→      { type: 0x0016 }, { type: 0x000b }, { type: 0xff01 }, { type: 0x0000 },
   653→      { type: 0x0017 }, { type: 0x000d }, { type: 0x000a }, { type: 0x0023 },
   654→      { type: 0x0010, alpnProtocols: ['h2', 'http/1.1'] }, { type: 0x002b },
   655→      { type: 0x002d }, { type: 0x0033 }, { type: 0x001c }, { type: 0x0015 },
   656→    ],
   657→    supportedGroups: [0x001d, 0x0017, 0x0018],
   658→    signatureAlgorithms: [0x0403, 0x0804, 0x0401, 0x0503, 0x0501, 0x0803, 0x0601, 0x0201],
   659→    alpnProtocols: ['h2', 'http/1.1'],
   660→  };
   661→
   662→  const { tlsOptions, unsupported } = impersonate(CHROME_SPEC);
   663→
   664→  const url = new URL(targetUrl);
   665→  const tlsSocket = tls.connect({
   666→    host: url.hostname,
   667→    port: 443,
   668→    servername: url.hostname,
   669→    ...tlsOptions,
   670→  });
   671→
   672→  await new Promise((resolve, reject) => {
   673→    tlsSocket.once('secureConnect', resolve);
   674→    tlsSocket.once('error', reject);
   675→    setTimeout(() => reject(new Error('TLS timeout')), 10000);
   676→  });
   677→
   678→  const path = (url.pathname || '/') + (url.search || '');
   679→  tlsSocket.write(`GET ${path} HTTP/1.1\r\nHost: ${url.hostname}\r\nUser-Agent: Mozilla/5.0...\r\nConnection: close\r\n\r\n`);
   680→
   681→  // ... collect response chunks, return
   682→}
   683→```

   813→| Function invocation (sync, 200ms avg) | **~0.0006 credits** (negligible) |

   815→| Function downloading 10 MB from internet | **0 credits** (ingress not charged) |
   816→| Function writing 1 MB to Blobs | **0 credits** (blob storage unmetered) |
   817→| Function reading 1 MB from Blobs | **0 credits** (blob API unmetered) |
   818→| Production deploy | **15 credits** (avoid) |
   819→
   820→**Bottom line for scraping use case:**
   821→- Downloading data through a function = FREE (ingress)
   822→- Returning scraped data as function response = costs bandwidth (20 cr/GB)
   823→- Storing scraped data in Blobs from function = FREE
   824→- Reading scraped data back via Blobs API = FREE
   825→
   826→**Optimal pattern:** Function scrapes → writes to Blobs (free) → returns tiny "ok" response (free) → client reads scraped data via Blobs API (free). Total cost: ~0.0006 credits per scrape (compute only) = ~500,000 scrapes/month on Free plan.

   830→# Part 11: Function Logs as a Third Free Egress Channel (Validated 2026-08-14T22:00Z)
   831→
   832→## The discovery
   833→
   834→Function logs ARE accessible via the Netlify CLI and capture `console.log()` output from the function — confirming they can be used as a **third free egress channel** alongside Blobs API and HTTP response bodies.
   835→
   836→## How to use function logs as data exfil
   837→
   838→### Function side (writes data to logs)
   839→
   840→```js
   841→// functions/log-exfil.mjs — v1 ESM handler pattern
   842→export async function handler(event, context) {
   843→  const data = event.queryStringParameters?.data || 'default';
   844→  const ts = new Date().toISOString();
   845→  const requestId = context?.awsRequestId;
   846→
   847→  // Log structured JSON lines — readable via `netlify logs --json`
   848→  console.log('==========DATA_START==========');
   849→  console.log(JSON.stringify({ request_id: requestId, timestamp: ts, payload: data }));
   850→  console.log('==========DATA_END==========');
   851→
   852→  return {
   853→    statusCode: 200,
   854→    body: JSON.stringify({ ok: true, request_id: requestId }),
   855→  };
   856→}
   857→```
   858→
   859→### Reader side (retrieves logs as JSON Lines)
   860→
   861→```bash
   862→# Get last hour of logs as JSON Lines
   863→netlify logs --json --since 1h --function log-exfil
   864→
   865→# Live tail
   866→netlify logs --follow --function log-exfil
   867→
   868→# Filter by level (info, warn, error)
   869→netlify logs --json --since 24h --level error
   870→
   871→# Parse with jq
   872→netlify logs --json --since 1h --function log-exfil | jq -r 'select(.message | startswith("{")) | .message' | jq .
   873→```

   876→
   877→| Output type | Captured? | Notes |
   878→|---|---|---|
   879→| `console.log('HELLO')` | ✅ | Plain string |
   880→| `console.log(JSON.stringify({...}))` | ✅ | JSON-parseable per line |

   883→| Stack traces on errors | ✅ | Multi-line, captured per line |
   884→| Function `Response.json()` body | ❌ | Not logged (only console.* output) |
   885→
   886→## Critical limitation: v1 vs v2 handler
   887→
   888→| Handler style | Example | `console.log` captured? |
   889→|---|---|---|
   890→| **v1 ESM** (`.mjs`, `export async function handler(event, context)`) | `log-exfil.mjs` | ✅ Yes |
   891→| **v1 CommonJS** (`.js`, `exports.handler = async (event, context) => {...}`) | — | ✅ Yes |
   892→| **v2 modern** (`.mjs`, `export default async function handler(req, context)`) | `scrape.mjs` | ❌ No (empty INFO line only) |
   893→
   894→**Use v1 ESM handlers (`.mjs` + `export async function handler`) when you need logs as egress.** The v2 modern `Request/Response` API handler doesn't expose console.log to Netlify's observability stack the same way.
   895→
   896→## Log retention and limits
   897→
   898→Per [Function logs docs](https://docs.netlify.com/build/functions/logs.md):
   899→
   900→| Plan | Retention | Per-invocation limit |
   901→|---|---|---|
   902→| Free | **24 hours** | 4 KB total (Lambda compatibility mode) |
   903→| Personal/Pro | 7 days | 4 KB |
   904→| Enterprise (via Log Drains) | Configurable | 700 KB per single log entry |
   905→
   906→If a single invocation's log output exceeds 4 KB, **only the last 4 KB is retained** — the rest is truncated. So for large data dumps, you must:
   907→- Chunk into multiple invocations (each ≤ 4 KB), OR
   908→- Use Blobs API instead (no size limit, free)
   909→
   910→## Cost: 0 credits
   911→
   912→| Action | Cost |
   913→|---|---|
   914→| `console.log()` from function | 0 credits (just compute ~0.0006 cr per invocation) |
   915→| `netlify logs --json` retrieval | 0 credits (CLI command, not an API meter) |
   916→| Log storage (24h) | 0 credits (Free plan retention) |
   917→
   918→## When to use logs vs Blobs vs HTTP response
   919→
   920→| Use case | Best channel | Why |
   921→|---|---|---|
   922→| Large scraped data (>4 KB) | **Blobs** | No size limit, free, persistent |
   923→| Small structured records (≤4 KB) | **Logs** | Easy to retrieve, parseable JSON Lines |
   924→| Status / pointer / metadata | **HTTP response** | Returns immediately, no extra call needed |
   925→| Audit trail / debug | **Logs** | Auto-timestamped, filterable by level |
   926→| Real-time streaming | **Logs (`--follow`)** | Live tail mode |

   928→## Combined scraping pattern (all 3 channels)
   929→
   930→```js
   931→// Function does all 3:
   932→export async function handler(event, context) {
   933→  const targetUrl = event.queryStringParameters?.url;
   934→  const r = await fetch(targetUrl);
   935→  const body = await r.text();
   936→
   937→  // 1. WRITE TO BLOBS (large data, persistent, free)
   938→  const { getStore } = await import('@netlify/blobs');
   939→  const store = getStore('scrapes');
   940→  const blobKey = `scrape-${Date.now()}`;
   941→  await store.setJSON(blobKey, { url: targetUrl, body, ts: new Date().toISOString() });
   942→  await store.setJSON('latest', { blob_key: blobKey });
   943→
   944→  // 2. LOG METADATA (small structured data, 24h retention, free)
   945→  console.log(JSON.stringify({
   946→    blob_key: blobKey,
   947→    target_url: targetUrl,
   948→    response_size: body.length,
   949→    status: r.status,
   950→    timestamp: new Date().toISOString(),
   951→  }));
   952→
   953→  // 3. RETURN SMALL RESPONSE (pointer to blob, free)
   954→  return {
   955→    statusCode: 200,
   956→    body: JSON.stringify({
   957→      ok: true,
   958→      blob_key: blobKey,  // Client fetches body via Blobs API
   959→      size: body.length,
   960→    }),
   961→  };
   962→}
   963→```
   964→
   965→Client retrieval:
   966→```bash
   967→# Option A: Read the blob (large data, free)
   968→curl -H "Authorization: Bearer $TOKEN" \
   969→  "https://api.netlify.com/api/v1/blobs/$SITE_ID/site:scrapes/$BLOB_KEY"
   970→
   971→# Option B: Read the logs (small structured data, free, 24h)
   972→netlify logs --json --since 1h --function <name>
   973→```
